## Open Questions

- **Review changes with nothing changed (criterion 2.5, third).** Proven: the product shows a disabled "Review changes · 0" button with the tooltip "No changes yet", and the review screen does not open, so no empty screen exists. This behaviour comes from spec 004. Not proven: an empty review screen, because there is none. Decision needed: keep the disabled button, or add an empty screen.
- **"The brain tells the user" after Don't start (criterion 2.3).** Proven with the fake brain only: the note reaches the brain and a scripted reply shows in the chat. No real provider turn was run. This spec has no approval for one.
- **"The brain answers from that repository's files" (criterion 2.1, third).** Proven: the e2e shows the brain is launched with every repository readable, and a read succeeds under the fake. Not proven: a real brain turn.
- **Session started before this change (criterion 2.5, fifth).** The real proof is the unit test `older-sessions.test.ts`, which seeds old-design rows and branches. The e2e only approximates it with a session whose workers made a branch in every repository.
- **Fixture differences.** The e2e uses branches dev, main and dev where the criterion says main, develop and dev. The project added mid-session is web, not infra. The behaviour under test does not depend on those names.
- **Known gap: a project removed from the group while a queued worker still waits on its unsaved-changes card.** The card is cancelled, but the worker stays queued. It can reopen and cancel the question again when workers are re-evaluated. Likely fix: fail such a worker with a reason. Product decision needed.
- **A removed project that returns to the group is no longer asked about mid-session.** Its switch back happens at the next session open.
- **Accessibility.** The checks are jsdom assertions on roles, names and focus. No automated checker such as axe was run, and no manual screen-reader pass was done.
- **Waiting merge and `open` (review-changed.test.ts "is pushed when a waiting merge lands").** The test now calls `open` again until the push arrives, because `open` returns faster and its background merge retry skips a repository whose merge is still finishing. Not a regression in real use: a skipped repository has a merge in flight, and that merge retries the waiting update itself when it ends. Later triggers are the next `open` (a person acts in seconds, not milliseconds), the next merge in that repository, and the final summary, which retries without skipping. The test window is artificial. Run 5 times: 4 of 4 passed each time. Not changed in the product.
- **Flaky tests.** None seen. The full unit run (392 files, 4,985 tests) and the full e2e run (334 tests) passed on the first run with no failures and no reruns.
- **Criteria count.** This file and its notes say "24 criteria"; the functional spec has 25.
